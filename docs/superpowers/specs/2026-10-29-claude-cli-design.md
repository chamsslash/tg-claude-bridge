# Мост на `claude -p` вместо облачной рутины, еда по фото в Yazio

## Зачем

Рутина жила в облаке: пробуждение — десятки секунд, каждое сообщение боту —
запуск из дневного лимита, ответ — через `scripts/say.py` с токеном бота в
окружении рутины, а Gmail и Календарь — коннекторами с правом записи в той
же сессии, что читает чужие письма. Теперь мост сам вызывает `claude -p` на
том же сервере с долгоживущим токеном подписки (`claude setup-token`), как
это уже сделано в `mpei-mail-api`. Оттуда же взят код изоляции, Google,
сводки Gmail и календаря.

Бот один: Gmail, Календарь и еда. С ботом МЭИ (`mpei-mail-api`) он не
связан; Gmail и Календарь из того бота нужно убрать отдельно, иначе сводки
придут дважды.

## Модель угроз

Claude читает чужой текст: письма Gmail и названия встреч из приглашений.
Атакующий через него хочет украсть секреты (токены Google, Telegram,
пароль Yazio), действовать от имени владельца или обмануть его текстом.

Принцип: в одном запуске не сходятся чужой текст, приватные данные и канал
наружу. **Claude только возвращает текст или JSON; всё делает сервис.**

Жёсткое разделение: запуски с чужим текстом (сводка Gmail, команды
календаря со списком событий) идут **без единого инструмента** — никакая
команда из письма или приглашения не выполняется ни Claude, ни сервисом.
Веб (WebSearch, WebFetch) есть только у еды по фото: на входе там лишь фото
и подпись владельца, а в Yazio пишет сервис. Почта учебная, сервис личный —
риск принят владельцем осознанно.

## Слои

1. **Claude без инструментов.** `claude -p --restricted --tools ""
   --strict-mcp-config` с пустым MCP-конфигом, `--no-session-persistence`,
   свой системный промпт, `--json-schema` там, где нужен JSON. Запрос еды
   несёт `web: true` — тогда `--tools WebSearch,WebFetch --allowedTools
   WebSearch,WebFetch` и до 20 ходов (поиск одного продукта — около 10);
   других инструментов нет и тут. Вход —
   одна строка stream-json (`--input-format stream-json --output-format
   stream-json --verbose`): так в запуск можно положить картинку.
2. **Отдельный контейнер `claude`.** Только токен Claude (`claude.env`),
   корневая ФС только для чтения, tmpfs, `cap_drop: ALL`, внутренняя сеть;
   наружу только через `egress`.
3. **`egress`** — CONNECT-прокси: по умолчанию `*:443` — любой хост на
   443, если все его адреса публичные (не частные сети, не loopback, не
   link-local с метаданными облака, не CGNAT); соединение — на уже
   проверенный адрес. `EGRESS_ALLOW=api.anthropic.com:443,platform.claude.com:443`
   возвращает прежний режим «только Anthropic» (еда тогда без веба).
4. **`claude-runner`** — `POST /run` {system, prompt, schema, images, web};
   флаги зашиты в обёртку. Тесты сводки и календаря падают, если их запрос
   уходит с `web`.
5. **Проверка на входе и выходе в сервисе**: чужой текст в тегах с
   экранированием, в ответах Claude вырезаются ссылки и режется длина, числа
   проверяются.
6. **Бюджет:** не больше `LLM_PER_HOUR` запусков в час (по умолчанию 40).

## Что делает бот

### Сводка Gmail (только чтение)

Раз в час — новые письма входящих; по кнопке «📧 Gmail» — за сутки. Claude
возвращает по письму `kind` (main/other), суть, «⚠️ Нужно», код;
отправителя, тему, дату и вложения подставляет сервис. Рассылки (other)
отбрасываются; плановая сводка без писем молчит. Код 🔑 — только если он
буквально есть в письме. Без Claude плановая сводка ждёт следующего часа.
Gmail API, scope `gmail.readonly`.

### Календарь

- Кнопка «📆 Календарь» — сегодня и завтра шаблоном, без Claude.
- Свободный текст — команда календаря: Claude возвращает одно действие
  `create` / `move` / `delete` / `none`. Поставить и перенести — сразу, с
  «↩️ Отменить»; удалить — с подтверждением. Только основной календарь, без
  участников, переносит и удаляет только свои события. Calendar API, scope
  `calendar.events`.

### Еда по фото

Кнопка «🍽 Калории (ИИ)» → приём пищи → фото и описание в любом порядке
(или блюдо из базы кнопкой вместо описания) → сервис скачивает фото из
Telegram → Claude по картинке, подписи и базе блюд возвращает JSON → сервис
проверяет числа, ищет покупное в базе Yazio и пишет в дневник по записи на
каждое блюдо и напиток, одним запросом → ответ с разбивкой, остатком на
сегодня и «↩️ Отменить». Фото без кнопки тоже записывается.

Claude возвращает:

```json
{"is_food": true, "daytime": "lunch",
 "dishes": [{"name": "Гречка с курицей", "saved": "",
   "items": [{"name": "гречка отварная", "grams": 180, "kcal": 198, "protein": 7, "fat": 2, "carb": 39}]},
  {"name": "Шорли яблочный", "saved": "", "product": {"brand": "ВкусВилл", "query": "шорли яблочный"},
   "items": [{"name": "шорли яблочный", "grams": 500, "kcal": 140, "protein": 0, "fat": 0, "carb": 35}]}],
 "reply": ""}
```

- Claude сначала оценивает вес всей порции по посуде и приборам, потом
  делит его по компонентам; вес из подписи важнее оценки. Каждое блюдо и
  напиток — отдельно, напиток без калорий не пишется.
- Покупное — по данным: таблица пищевой ценности на фото, иначе состав
  из интернета. Домашнюю еду Claude оценивает сам, а если не уверен — в
  калорийности, составе или весе порции — сверяется в интернете. Всего не
  больше трёх поисков на запрос. `product` — бренд и 2–4 слова названия
  без бренда, только у покупного, у такого блюда один компонент.

- `is_food: false` — не еда: владельцу уходит `reply`, в Yazio ничего.
- `daytime` не из `breakfast/lunch/dinner/snack` — по часу по Москве:
  04–11 завтрак, 11–16 обед, 16–22 ужин, иначе перекус.
- Итог блюда считает сервис суммой `items`; блюдо меньше 1 ккал
  пропускается.
- Проверки: 1–6 блюд, 1–15 компонентов в блюде; граммы 0–2000, ккал 0–3000,
  БЖУ 0–300 г на компонент; итог приёма до 5000 ккал. Вне пределов — «не понял, что на фото».
  Названия — одна строка без ссылок, до 80 (компонент) и 100 (запись)
  символов. Подпись — внутри `<подпись>`, теги в ней экранируются.
- Правка сообщения с фото не пишет еду повторно. Альбом — запись на фото.
  Картинка файлом — просьба прислать как фото.

Ответ:

```
🍽 Обед · Гречка с курицей
≈ 620 ккал · Б 38 · Ж 18 · У 72

• гречка отварная, ~180 г — 198 ккал
• куриная грудка, ~150 г — 240 ккал

Записал в Yazio.
```

После «Записал в Yazio.» — остаток на сегодня из
`GET /v22/user/widgets/daily-summary?date=`: съедено (сумма приёмов) против
целей, сожжённое прибавляется к цели, если так настроено в приложении. Не
прочиталось — ответ без этих строк.

«↩️ Отменить» удаляет все записи приёма (каждую своим видом) и проверяет
удаление чтением дня; живёт 7 дней и срабатывает один раз.

#### Продукт из базы Yazio

Блюдо с `product` сервис ищет в базе Yazio: сначала «бренд запрос», потом
«запрос» — поиск требует в названии все слова, и бренд, которого в
названии нет, всё ломает. Берётся первый результат в г или мл, у которого
производитель совпал с брендом (без регистра, пробелов, ё/е; одно содержит
другое), а калории на 100 г отличаются от оценки Claude не больше чем на
15% или 8 ккал. Тогда запись — продукт из базы весом из оценки Claude, КБЖУ
в ответе и в базе блюд — по Yazio, у компонента пометка «· база Yazio».
Не нашлось или поиск не ответил — «быстрый ввод» с числами Claude. Записи
базы Yazio добавляют пользователи, и ошибки в них бывают: оценка Claude с
этикетки или из интернета их проверяет.

#### База блюд

Владелец готовит сам, и блюд у него немного. Каждое новое записанное блюдо
сохраняется в `state.json` (название, состав, сколько раз и когда ели); до
60 блюд, лишние — самые редкие и давние. Фото в сценарии без описания —
вопрос «что это?» и до 6 блюд кнопками, сначала частые. Нажатие отдаёт
Claude название и прошлый состав: состав тот же, вес — заново по фото.
Список базы (id и названия) Claude видит всегда и возвращает `saved`, если
узнал блюдо; `saved` не из базы — блюдо новое, то же название без `saved`
— то же блюдо. Отмена приёма убирает из базы добавленные им блюда, если их
с тех пор не выбирали. Названия в промпте — без угловых скобок.

#### Yazio

Публичного API нет; сервис ходит в API мобильного приложения
`https://yzapi.yazio.com/v22` (справочник —
[yazio-community/yazio-api-specification](https://github.com/yazio-community/yazio-api-specification)).
Проверено 28.10.2026 на аккаунте владельца, формат записи совпал с
перехваченным запросом приложения для iPad.

| Зачем | Запрос |
|---|---|
| Вход | `POST /v22/oauth/token`, JSON `{grant_type:"password", username, password, client_id, client_secret}` → `{access_token, expires_in, refresh_token}` |
| Записать | `POST /v22/user/consumed-items`, `{"products":[],"recipe_portions":[],"simple_products":[{id, date, daytime, name, nutrients, is_ai_generated:false}, …]}` → 204; несколько записей в одном запросе проверены 29.10.2026 |
| Итог дня | `GET /v22/user/widgets/daily-summary?date=` → `goals`, `meals.<приём>.nutrients`, `activity_energy`, `consume_activity_energy` |
| Записать продукт | в том же `POST`, `"products":[{id, product_id, amount, serving:null, serving_quantity:null, daytime, date}]` — `amount` в г или мл продукта; проверено 29.10.2026, вместе с `simple_products` в одном запросе тоже |
| Профиль | `GET /v22/user` → `sex`, `food_database_country` (нужны поиску; выдача от пола зависит) |
| Найти продукт | `GET /v22/products/search?query&sex&countries` → `[{product_id, name, producer, base_unit, nutrients (на 1 г/мл)}]` |
| Прочитать день | `GET /v22/user/consumed-items?date=ГГГГ-ММ-ДД` → `products`, `simple_products` |
| Удалить | `DELETE /v22/user/consumed-items`, `{"simple_products":"<id>"}` или `{"products":"<id>"}` (строка) → 204 |

- `client_id` / `client_secret` — общая пара приложения из спеки.
- Без `User-Agent` известной версии приложения всё, кроме входа, отвечает
  `403 version_blocked`; строка — в `YAZIO_USER_AGENT`, по умолчанию
  `YAZIO/26.30.1 (com.yazio.ios.YAZIO; build:2607271240; iOS 27.0.0) Ktor`.
- `id` — UUID клиента; `date` — `ГГГГ-ММ-ДД ЧЧ:ММ:СС` по Москве;
  `nutrients` — итог на порцию: `energy.energy`, `nutrient.protein`,
  `nutrient.fat`, `nutrient.carb`.
- Удаление отвечает 204 и когда ничего не удалило — проверка чтением дня.
- Токен — в памяти; 401 — вход заново один раз.

## Что уходит

`internal/routine`, `ROUTINE_*`, `scripts/say.py`, systemd-юнит. Мост
переезжает в docker compose (три контейнера, как у `mpei-mail-api`).
Отправка писем и поиск по почте текстом, которые умела рутина, не
переносятся: у Claude, читающего почту, нет инструментов, а писать письма
от имени владельца по пересказу чужого текста — ровно то, от чего защищает
модель угроз.

## Настройки

| Переменная | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | обязательна |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REFRESH_TOKEN` | все три или ничего; refresh-токен — `tg-bridge google-auth` на ноутбуке |
| `YAZIO_USERNAME`, `YAZIO_PASSWORD` | оба или ничего |
| `YAZIO_USER_AGENT` | строка версии приложения |
| `CLAUDE_URL` | ставит compose |
| `LLM_PER_HOUR`, `CLAUDE_TIMEOUT`, `GMAIL_POLL_INTERVAL`, `REQUEST_TIMEOUT`, `POLL_TIMEOUT`, `TELEGRAM_CHAT_ID`, `STATE_PATH` | необязательные |

Токен Claude — в `claude.env`, его получает только контейнер `claude`.

## Решения автора (не обсуждались отдельно)

- Порядок: переезд и еда — одной веткой; код Gmail и Календаря перенесён из
  `mpei-mail-api` почти без изменений.
- Здоровье: о Gmail и Claude, лежащих дольше порога, бот пишет сам.
- `is_ai_generated: false`, как отправляет приложение.
- Запись на блюдо, а не на компонент: в дневнике блюдо, разбивка — в чате.
- База блюд — в состоянии моста, а не в Yazio; название блюда — от Claude.
- Продукт из базы Yazio — только при совпадении бренда и калорий (15% или
  8 ккал на 100 г); иначе верим Claude, а не базе.
- Пол и страна для поиска — из профиля Yazio, читаются один раз.
- Веб — WebSearch и WebFetch; egress открыт на 443 для всех публичных
  адресов, а не по списку сайтов: заранее не угадать, где лежит состав.
