# tg-claude-bridge

Личный Telegram-бот: сводка Gmail раз в час, команды Google Календаря
текстом и еда по фото в дневник Yazio. Думает Claude — `claude -p` на том же
сервере с долгоживущим токеном подписки: данные собирает и действия
выполняет сам мост. Почту и календарь Claude разбирает вовсе без
инструментов; у еды есть веб — свериться с составом и калорийностью.

```
сообщение боту
   │  мост держит длинный опрос getUpdates
   ▼
bridge ──(llm)──▶ claude (claude -p) ──▶ egress ──▶ Anthropic, веб для еды
   │
   ├─ Gmail API (только чтение) — сводка раз в час и по кнопке
   ├─ Calendar API — поставить / перенести / удалить по тексту
   └─ Yazio — запись по фото еды: «быстрый ввод» или продукт из базы
```

Проектное решение и модель угроз —
[docs/superpowers/specs/2026-10-29-claude-cli-design.md](docs/superpowers/specs/2026-10-29-claude-cli-design.md).

## Что умеет бот

- **«📧 Gmail за сутки»** — пересказ писем за сутки, рассылки отсеяны. Та же
  сводка по новым письмам приходит сама раз в час и молчит, если писать не о
  чем. Коды подтверждения — отдельной строкой 🔑, только если код буквально
  есть в письме.
- **«📆 Календарь»** — события на сегодня и завтра.
- **Текст** — команда календаря: «поставь созвон завтра в 15», «перенеси
  созвон на пятницу», «удали тренировку в четверг». Поставить и перенести —
  сразу, с «↩️ Отменить»; удалить — после подтверждения.
- **«🍽 Калории (ИИ)»** — выбрать приём пищи, прислать фото и описание.
  Вместо описания можно нажать блюдо из своей базы: туда попадает каждое
  новое записанное блюдо, кнопками — самые частые. Claude оценивает вес
  порции и компонентов и КБЖУ; блюдо и напиток на одном фото — отдельные
  записи в одном приёме. Покупное (шорли, йогурт, батончик) — по этикетке
  на фото или по составу из интернета; если такой же продукт есть в базе
  Yazio, пишется он, с пометкой «база Yazio». В ответе — разбивка, остаток
  на сегодня по целям Yazio и «↩️ Отменить» (убирает весь приём и только
  что добавленные в базу блюда). Фото без кнопки тоже записывается, приём
  угадывается по времени.

Чего бот не делает: не отправляет письма и не ищет по почте текстом — это
умела облачная рутина, но у Claude, читающего почту, теперь нет
инструментов, а писать письма от имени владельца по пересказу чужого
текста — ровно то, от чего защищает модель угроз.

Два решения, которые стоит знать:

**Чужие чаты отбрасываются молча.** Боту может написать кто угодно, кто его
найдёт. Ответ вроде «доступ запрещён» подтвердил бы постороннему, что бот
живой и за ним что-то есть, поэтому ответа нет никакого.

**Offset двигается после обработки.** Падение посреди работы означает повтор
команды, а не её потерю. Повтор человек заметит и переживёт, потерю — нет.

## Настройка

Чат зашит в код (`internal/config/config.go`) — это не секрет, а адрес
получателя. Токена бота в репозитории нет, см. «Почему токен бота только в
окружении» ниже.

`.env` (шаблон — `.env.example`):

| Переменная | Обязательна | Что это |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | токен бота от @BotFather |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REFRESH_TOKEN` | нет, все три вместе | Gmail и Календарь, см. «Google» |
| `YAZIO_USERNAME`, `YAZIO_PASSWORD` | нет, оба вместе | еда по фото, см. «Yazio» |
| `YAZIO_USER_AGENT` | нет | версия приложения Yazio, см. «Yazio» |
| `TELEGRAM_CHAT_ID` | нет | перекрывает зашитый чат |
| `GMAIL_POLL_INTERVAL` | нет | как часто сводка Gmail, по умолчанию `1h`, минимум `10m` |
| `LLM_PER_HOUR` | нет | потолок запусков Claude в час, по умолчанию `40` |
| `CLAUDE_TIMEOUT`, `REQUEST_TIMEOUT`, `POLL_TIMEOUT` | нет | таймауты: `8m`, `1m`, `50s` |

`claude.env` (шаблон — `claude.env.example`) — `CLAUDE_CODE_OAUTH_TOKEN`, его
получает только контейнер `claude`.

Без Google, Yazio или токена Claude мост стартует: соответствующая часть
просто отвечает «не настроено». Без токена бота — не стартует намеренно.

### Почему токен бота только в окружении

Сначала он был зашит в код вместе с чатом — репозиторий личный, так проще
разворачивать. За сутки пришлось выпустить три токена подряд: каждый вскоре
после пуша начинал отвечать `409 Conflict: terminated by other getUpdates
request`, то есть очередь бота читал кто-то ещё.

Репозиторий публичный, а очередь бота Telegram отдаёт только одному
читателю: любой, кто нашёл токен, отбирает сообщения у настоящего сервиса.
Telegram при этом не входит в партнёрскую программу GitHub secret scanning
(см. [таблицу паттернов][gh-patterns], у `telegram_bot_token` в колонке
Partner стоит «✗»), так что утёкший токен никто не отзывает — он просто
остаётся живым и публичным.

[gh-patterns]: https://docs.github.com/en/code-security/reference/secret-security/supported-secret-scanning-patterns

### Токен Claude

На ноутбуке, где Claude Code залогинен в твой аккаунт:

```bash
claude setup-token
```

Токен живёт около года и годится только для запросов к модели — коннекторы
claude.ai с ним не работают, и они не нужны. Никуда, кроме `claude.env` на
сервере, его не вставляй.

### Google

Можно пропустить — тогда Gmail и Календарь выключены.

1. [console.cloud.google.com](https://console.cloud.google.com) → новый
   проект. Биллинг не нужен.
2. **APIs & Services → Library** — включить **Gmail API** и **Google
   Calendar API**.
3. **Google Auth Platform → Branding / Audience**: тип External, затем
   **Publish app** («In production»). В статусе «Testing» refresh-токен живёт
   7 дней. Проверку Google для личного использования проходить не нужно: при
   входе будет «Google hasn't verified this app» → **Advanced → Go to …**.
4. **Clients → Create client → Desktop app** — Client ID и Client secret.
5. На ноутбуке, из этого репозитория:

   ```bash
   GOOGLE_CLIENT_ID='…' GOOGLE_CLIENT_SECRET='…' go run ./cmd/tg-bridge google-auth
   ```

   Войди своим Gmail и разреши доступ — в терминале появится
   `GOOGLE_REFRESH_TOKEN=…`.

Права: `gmail.readonly` (письма только читать) и `calendar.events` (события;
приглашений мост не рассылает).

Если тот же Gmail и Календарь подключены к другому боту (например, к боту
МЭИ из `mpei-mail-api`), там их нужно выключить — иначе сводки придут
дважды.

### Yazio

Публичного API у Yazio нет: мост ходит в API мобильного приложения, как само
приложение (подробности — в спеке). Нужны почта и пароль входа. Если входил
через Google, пароль задаётся в приложении через «Забыли пароль?».

Yazio пускает только известные версии приложения: без подходящего
`User-Agent` всё отвечает `403 version_blocked`, и бот пишет «обнови
YAZIO_USER_AGENT». Тогда нужна строка версии посвежее — например, из
перехваченного запроса приложения.

Android-приложение Yazio кэширует дневник и подтягивает записи с других
устройств лениво — после своей записи или повторного входа. Поэтому разбивка
всегда приходит и в Telegram.

## Развёртывание

Три контейнера на одном сервере: `bridge`, `claude` (Claude Code CLI только
с токеном Claude; инструменты — лишь WebSearch и WebFetch и лишь в запусках
с едой) и `egress` (единственный выход `claude` наружу: 443 к публичным
адресам, не к соседним контейнерам и не на хост; `EGRESS_ALLOW` сужает
до Anthropic, еда тогда без веба). Входящих соединений нет.

Нужно: Docker с Compose v2.24+, ~3 ГБ диска на сборку (образ `claude` ~800 МБ),
~1,5 ГБ памяти, подписка Claude. Сервер — зарубежный: Anthropic не
обслуживает российские адреса.

```bash
git clone https://github.com/chamsslash/tg-claude-bridge.git \
  /mnt/data/projects/tg-claude-bridge
cd /mnt/data/projects/tg-claude-bridge
./deploy.sh   # первый раз создаст .env и claude.env из шаблонов и остановится
# заполнить .env и claude.env
./deploy.sh
```

Скрипт пересоберёт образы, перезапустит контейнеры и дождётся, пока бот
начнёт слушать. `--no-pull` — без `git pull`.

### Переезд с рутины

1. **Остановить старый мост**: `sudo systemctl disable --now tg-bridge`,
   затем `sudo rm /etc/systemd/system/tg-bridge.service`. Telegram отдаёт
   очередь бота одному читателю — deploy.sh со старым юнитом не стартует.
2. **Выключить рутину** в `claude.ai/code/routines` и удалить её API-токен.
3. `ROUTINE_URL` и `ROUTINE_TOKEN` из `.env` удалить; каталоги `bin/` и
   `state/` больше не нужны.

## Проверка

1. `/start` — кнопки на месте.
2. «📧 Gmail за сутки» — «Смотрю…», затем сводка. «Claude сейчас не
   ответил» — смотри `docker compose logs claude`: чаще всего пустой или
   протухший `CLAUDE_CODE_OAUTH_TOKEN`.
3. «поставь тестовую встречу завтра в 10» → «📆 Поставил…» → «↩️ Отменить».
4. «🍽 Калории (ИИ)» → «Обед» → фото → описание → «🍽 Считаю…» → разбивка,
   остаток на сегодня, «↩️ Отменить». Второй раз то же блюдо — кнопкой.

Логи: `docker compose logs -f bridge claude egress`. Попытки `claude` выйти
во внутреннюю сеть видны в логе `egress`.

## Обслуживание

- **Обновить Claude Code** — `CLAUDE_CODE_VERSION` в `Dockerfile` и
  `./deploy.sh`. Автообновление в контейнере выключено намеренно.
- **Токен Claude истёк** (бот пишет «⚠️ Claude: нет связи», в логе `claude` —
  «Not logged in») — новый `claude setup-token` в `claude.env`,
  `docker compose up -d claude`.
- **Google отозвал доступ** («Google не принял refresh-токен») — снова
  `google-auth`, новый `GOOGLE_REFRESH_TOKEN`, `docker compose up -d bridge`.
- **Расход подписки**: не больше `LLM_PER_HOUR` запусков в час. Обычный
  день — до 24 сводок Gmail, команды календаря и фото еды.
- Состояние (offset бота, что из Gmail уже ушло, кнопки «Отменить», база
  блюд) — в томе `bridge_data`.
